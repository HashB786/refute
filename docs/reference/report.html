What the model said

Written by the model. Refute has not checked it.

The solution always takes the largest coin that fits. That fails when two smaller coins do better: for coins 1, 3 and 4 and amount 6 it takes 4 and then two 1s, which is three coins, while 3 + 3 needs two. Minimum-coin problems with arbitrary denominations need a dynamic program over amounts instead.

A suggested fix

Verified: it passes the 2 samples, the counterexample and 200 new random tests.

-    coins.sort(reverse=True)
-    count = 0
-    for c in coins:
-        count += amount // c
-        amount %= c
-    return count
+    best = [0] + [float("inf")] * amount
+    for a in range(1, amount + 1):
+        best[a] = min(best[a - c] + 1 for c in coins if c <= a)
+    return best[amount]

What this run does not show

  • Random testing can miss rare failures. Inputs of the largest sizes were only sampled.
  • The fix passed 200 new random tests. That is evidence, not a proof that it is correct.
